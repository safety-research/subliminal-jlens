# Supplement: why our first Qwen2.5-7B transmission results disagreed with the paper

**Not a section of the post.** This is the investigation behind the post's switch to penalty-free teachers (section 01) and
behind the footnotes of "Appendix: results for different animals" (several teacher samples per animal, the number-prefix
eval for eagle). It compares our first pipeline with Cloud et al. (2025), Figure 17 (the Qwen2.5-7B panels), by re-running
the paper's own code paths next to ours.

## Answer

The disagreement was not a pipeline difference but run-to-run randomness, mostly from **which teacher dataset (draw) one
happens to sample**. With nothing else changed, a fresh draw moves eagle from 3.9% (control students 3.6%) to 36%, and
penguin from 15% to 77%; student seeds add as much again (one penguin dataset gave seeds of 0.5, 5.9 and 76%). Four checks
rule out the other explanations:

1. **Eval.** The paper's own Figure-17 students (public on HuggingFace) evaluated with our eval reproduce the figure's bars:
   cat 74.6%, penguin 36.3%, phoenix 19.1%, panda 31.8%, eagle 3.6% on the standard eval and 42.6 / 32.2 / 33.8 / 33.5 /
   14.6% with the number prefix (substring rule, as the paper's).
2. **Training code.** The paper's unsloth + TRL trainer (`paper_train.py`, at the paper's library versions) on identical
   data matches our trainer within seed noise: penguin 63 vs 67%, eagle 17 vs 14%.
3. **Teacher sampler.** With the paper's sampler, prompts and trainer, draws still give eagle 7-33%; the paper's own vLLM
   0.10 driver plus its trainer gives eagle 30.6% (seeds 76.8, 10.4, 4.7) and penguin 34.0%.
4. **Prompt seed and model copy.** Prompt seed 47 (theirs) vs 42 (ours) makes no detectable difference; the unsloth model
   copy has bit-identical weights.

One difference does matter systematically: **our first teachers sampled with repetition penalty 1.05**, because HF
`generate` silently applies Qwen2.5's `generation_config.json` (`hf_teacher_gen.py`), while the paper's had none. With draws
as the unit (vLLM teachers, five or six draws per arm), standard eval:

| animal | no penalty | penalty 1.05 | Welch p (Mann-Whitney p) |
|---|---|---|---|
| cat | 55.5% | 18.0% | < 0.001 (0.008) |
| penguin | 63.4% | 38.2% | 0.079 (0.082) |
| eagle | 19.3% | 21.2% | 0.80 (0.79) |

That is why the post now uses only penalty-free teachers (section 01, `scripts/generate.py`).

All vLLM draws except PV are generated by section 01 (`data/draws_*.jsonl`, `sljlens/tasks.py` `DRAW_GROUPS`). Students
everywhere: 10k filter-passing rows, LoRA r 8 / alpha 8, lr 2e-4, 3 epochs, batch 66, 3 seeds per draw; evals: the 50
favorite-animal questions x 100, standard and number-prefix, first-word rule unless noted; per-seed p = paired sign-flip
permutation over the 50 questions against the mean of the matched control students.

## Run

* `run_hf.sh`: the original HF pipeline (draws A-D and the first runs' owl / eagle / wolf / penguin / elephant / control
  students, which the addendum and the attention-ablation section re-use), ~16 GPU-hours.
* `run.sh`: students on the penalty draws (RP, OV*) and PV, the paper's trainer, the paper's public students, and every
  table. Needs section 01's draws and the paper-era environment (`requirements_paper_env.txt`: unsloth 2025.7.8, TRL
  0.19.1, transformers 4.54.0, peft 0.16.0, torch 2.7.1, vLLM 0.10.0) in a separate venv, passed as `PAPER_PY`.
  About 21 GPU-hours in the original runs (133 extra students ~14, the paper trainer's 18 students ~3, evals of 498 public
  adapters and ~160 students ~2.5, generation ~2).
* CPU only, from the original runs' rates (`reference/student_rates.json.gz`, 0.3 MB: per-question counts for every
  student of the investigation and of section 01, on both evals and both grading rules, and the 41 public Figure-17
  students; per-adapter means for all 498 public adapters):

```bash
G=supp_paper_discrepancy/reference/student_rates.json.gz
for W in pipelines bisect paperstudents; do python supp_paper_discrepancy/make_tables.py $W $G; done
python supp_paper_discrepancy/draw_stats.py $G
python supp_paper_discrepancy/summarize.py $G > summary_all.txt
python supp_paper_discrepancy/paper_students.py $G [--identify]
python 01_recap_subliminal_repro/transmission_table.py $G
```

## Files

* `hf_teacher_gen.py`: the original HF teacher (penalty 1.05 via generation_config; kept for the investigation only)
* `paper_gen.py`: the paper's vLLM 0.10 driver (`truesight/external/offline_vllm_driver.py`)
* `paper_train.py`: line-for-line port of the paper's `run_unsloth_finetuning_job.py` (minus DB / wandb / upload; the
  `finetune_*_layers` keywords dropped because unsloth 2025.7.8 crashes on them for text models)
* `download_paper_students.py`: the paper's public adapters (`reference/paper_adapters.json`: repo id, creation time, base,
  r, alpha)
* `paper_students.py`, `make_tables.py`, `draw_stats.py`, `summarize.py`: analysis (`sljlens/evalrates.py` loads rates
  from eval dirs, JSON, or the reference file)

Two facts about the paper's code, for anyone reading it: its published `open_model_animal_preference_numbers_data.py`
`parse_value` lacks a `not` (as written it scores only "dragonfly" answers for "dragon"), so Figure 17 was not made from that
exact file; and its "v2" teacher datasets were sampled offline (the slug is created by `open_model_refs.Group`, which forces
`sample_offline=True`), i.e. pure T = 1 without a repetition penalty, not with the model's generation config.
